# Upgrade study — Expo SDK 54 → 57

Status: **research only, nothing applied.** Written 2026-08-06 against `expo@57.0.11`.

Target: **Expo SDK 57.0.11** (React Native 0.86.2, React 19.2).
Current: **Expo SDK 54** (React Native 0.81.5, React 19.1).

The jump crosses three majors. SDK 57 itself is trivial — RN 0.86 shipped with
*no* user-facing breaking changes. **SDK 55 and especially SDK 56 carry all the
pain**, and SDK 56 is the wall: `expo-router` was decoupled from React
Navigation.

The repo is in good shape for this. New architecture is already on, there is no
`expo-av`, no legacy `expo-camera`/`expo-sqlite` API, no NativeWind. The work is
import rewiring, dependency bumps, one runtime risk (`fetch`) and one
performance risk (Hermes V1 + Reanimated).

---

## 1. What changed per SDK

| SDK | RN / React | What it does to this repo |
|---|---|---|
| **55** | 0.83 / 19.2 | Legacy architecture **removed**. Edge-to-edge mandatory on Android. `edgeToEdgeEnabled` and `notification` removed from app.json. Xcode 26 minimum. Node `^20.19.4` minimum. |
| **56** | 0.85 / 19.2 | **`expo-router` no longer depends on React Navigation.** `@expo/vector-icons` dropped from the `expo` package's dependencies. **`expo/fetch` becomes `globalThis.fetch`.** **Hermes V1 becomes the default engine.** iOS 16.4 minimum, Xcode 26.4 minimum. TypeScript 6.0.3. `expo-file-system` `copy()`/`move()` become async. |
| **57** | 0.86 / 19.2 | No breaking changes. `expo prebuild` now clears and regenerates native directories by default. More edge-to-edge fixes on Android. |

## 2. Toolchain: JDK, Gradle, Node

### JDK — unchanged, stay on 17

[DEV.md](../DEV.md) already requires **JDK 17** on `JAVA_HOME` (Temurin 17).
**That requirement does not move for SDK 57.** Expo's environment setup still
installs `zulu@17`, and React Native 0.86 still recommends JDK 17. Newer JDKs
remain a known source of Gradle breakage — keep 17.

### Gradle — 8.14.3 → 9.3.1 (major jump, mostly free)

The bare template's wrapper moves from `gradle-8.14.3` (SDK 54) to
`gradle-9.3.1` (SDK 57). Because `/android` is gitignored and regenerated by
`expo prebuild`, the wrapper upgrade comes for free.

The real exposure is the two config plugins that patch the generated
`android/app/build.gradle` with regex anchors. **Both were checked against the
SDK 57 template and all anchors still match** — the file is still Groovy DSL,
not Kotlin DSL:

| Plugin | Anchor | SDK 57 template | Status |
|---|---|---|---|
| [withCmakeVersion.js](../plugins/withCmakeVersion.js) | `/android\s*\{\n/` | `android {` present, no existing `externalNativeBuild` block | ✅ |
| [withReleaseSigning.js](../plugins/withReleaseSigning.js) | `/signingConfigs\s*\{\n/` | `signingConfigs { debug { … } }` present, still debug-only | ✅ |
| [withReleaseSigning.js](../plugins/withReleaseSigning.js) | `// see https://reactnative.dev/docs/signed-apk-android.` + `signingConfig signingConfigs.debug` | comment and line both unchanged | ✅ |

Both plugins throw loudly rather than silently no-op if an anchor ever stops
matching, so a future template change fails the build instead of shipping an
unsigned release. Re-verify after the first `expo prebuild` on 57 anyway.

The Windows `MAX_PATH` problem persists — `react-native-keyboard-controller`
goes `1.18.5 → 1.21.9` with longer codegen filenames. **Keep the CMake 3.31.6
pin.**

### Node — now a hard floor, and CI does not pin it

SDK 56 requires **Node ≥ 20.19.4**. [ci.yml](../.github/workflows/ci.yml) has
**no `setup-node` step** — it inherits whatever `ubuntu-latest` happens to ship.
Add an explicit `actions/setup-node` before starting the upgrade so a runner
image change cannot silently break the build.

## 3. Breakage in this repo, ranked

### 🔴 P0 — `expo-router` / React Navigation split (SDK 56)

Five files import from `@react-navigation/*`. The runtime API is unchanged —
**only the module specifier moves**, to `expo-router/react-navigation`.

| File | Import |
|---|---|
| [src/app/_layout.tsx:12](../src/app/_layout.tsx) | `ThemeProvider` ← `@react-navigation/native` |
| [src/theme/prophecyTheme.tsx:1-5](../src/theme/prophecyTheme.tsx) | `DarkTheme`, `DefaultTheme`, `type Theme` ← `@react-navigation/native` |
| [src/components/ui/app-fab.tsx:1](../src/components/ui/app-fab.tsx) | `BottomTabBarHeightContext` ← `@react-navigation/bottom-tabs` |
| [src/components/character-form.tsx:1](../src/components/character-form.tsx) | `BottomTabBarHeightContext` ← `@react-navigation/bottom-tabs` |
| [src/app/character/[id]/(tabs)/_layout.tsx:9](../src/app/character/[id]/(tabs)/_layout.tsx) | comment only — documents the `@react-navigation/elements` default header height of 64 |

Codemod handles it:

```bash
npx expo-codemod sdk-56-expo-router-react-navigation-replace src
```

Then **remove all three `@react-navigation/*` entries from package.json**.
`expo-doctor` gained a check that warns when `expo-router` and `react-navigation`
are both installed.

If a third-party library still imports from `@react-navigation/core`, the Expo
CLI rewrites it at bundle time. Disable with
`EXPO_ROUTER_DISABLE_RN_NAVIGATION_CHECK=1` if it misfires.

### 🔴 P0 — `expo/fetch` becomes the global `fetch` (SDK 56)

[src/repositories/campaigns.ts:77](../src/repositories/campaigns.ts) and
[:202](../src/repositories/campaigns.ts) call `fetch()` against the **self-hosted
campaign relay**, over cleartext HTTP (`usesCleartextTraffic: true` in
[app.json](../app.json)). SDK 56 swaps the implementation for a native
WinterTC-compliant stack — not React Native's. TLS, cleartext, redirect and
self-signed-certificate behaviour can all differ.

**Must be smoke-tested against a real relay** (attach server, join, leave/purge)
before shipping. Rollback lever: `EXPO_PUBLIC_USE_RN_FETCH=1`.

`WebSocket` in [src/lib/campaign-client.ts](../src/lib/campaign-client.ts) is
untouched — still React Native's.

### 🟠 P1 — `@expo/vector-icons` no longer transitive (SDK 56)

The `expo` package stopped depending on it. Two files import it:

- [src/app/_layout.tsx:1](../src/app/_layout.tsx) — the Paper `settings.icon` bridge
- [src/components/campaign-live-indicator.tsx:1](../src/components/campaign-live-indicator.tsx)

Fix: add `"@expo/vector-icons": "^15.0.2"` explicitly. The package is still
published and maintained.

Migrating to the scoped `@react-native-vector-icons/*` packages is **optional —
skip it for this upgrade.** The design-system icon set already comes from
[src/components/ui/icon.tsx](../src/components/ui/icon.tsx) via
`react-native-svg`; `@expo/vector-icons` is only Paper's fallback. Two import
sites make it cheap to revisit later.

### 🟠 P1 — Hermes V1 default + Reanimated memory regression

Hermes V1 became the default engine in SDK 56. Expo documents a **known issue:
importing `react-native-reanimated` causes a 25–30 % memory increase under
Hermes V1, affecting SDK 56 and 57.**

This repo does not import Reanimated directly, but
`react-native-keyboard-controller` does, and `KeyboardProvider` wraps the whole
app in [src/app/_layout.tsx](../src/app/_layout.tsx). **The regression applies.**

Mitigations, in order of preference:
1. Enable worklets bundle mode (Expo's documented workaround).
2. Opt out of Hermes V1 via `useHermesV1: false` in `expo-build-properties`.

Measure on a real low-end Android device before any tester build.

Hermes V1 also arrives **prebuilt** — SDK 56 ships precompiled XCFrameworks on
iOS and a Kotlin compiler plugin on Android. No build-from-source penalty. Free
wins: ~16 % faster iOS builds, ~40 % faster Android cold start.

### 🟠 P1 — lint / typecheck gates (CI breaks before the app does)

- **`eslint-config-expo` `^10.0.0` → `^57.0.1`.** Versioning was realigned to the
  SDK number; this is not a 47-major jump. React Compiler lint rules are **on by
  default** from SDK 55 — expect new lint failures.
- **TypeScript `~5.9.2` → `~6.x`.** The SDK 56 template ships 6.0.3.
  `bunx tsc --noEmit` is the real gate here, so budget time for new TS 6 errors.
- **The ajv trap will fire.** [CLAUDE.md](../CLAUDE.md) documents it: `bun.lock`
  pins ajv 6 at top level with ajv 8 nested under `expo-dev-launcher`. This
  upgrade regenerates the lockfile, so ajv 8 may re-hoist and ESLint dies at load
  with `Cannot set properties of undefined (setting 'defaultMeta')`. **After every
  install step, verify `node_modules/ajv` is 6.x.**

### 🟡 P2 — Android edge-to-edge

Mandatory since SDK 55; SDK 57 ships further fixes. [app.json](../app.json) has
no `edgeToEdgeEnabled` key, which is correct — the field was removed. SDK 54
already defaulted to edge-to-edge, so the risk is low.

Still re-verify on Android 15/16: [app-fab.tsx:37-38](../src/components/ui/app-fab.tsx)
and [character-form.tsx:42-43](../src/components/character-form.tsx) hand-compute
bottom padding from `BottomTabBarHeightContext` + `insets.bottom`, and
[`<TabPage>`](../src/components/ui/tab-page.tsx) owns FAB clearance for every
pager page.

### 🟡 P2 — `expo prebuild` clears native directories (SDK 57)

`/android` and `/ios` are gitignored, so regeneration is the intended flow and
both config plugins re-apply automatically (anchors verified above). The only
loss would be a manual edit inside `android/` — there should be none.

### 🟢 P3 — checked, **not** broken

| Change | Why this repo is safe |
|---|---|
| `expo-file-system` `copy()`/`move()` now async (56) | Zero usages. Only `File`, `Directory`, `Paths` are used — unchanged API. Callers: [db/backup.ts](../src/db/backup.ts), [lib/character-transfer-io.ts](../src/lib/character-transfer-io.ts), [lib/log/sink.native.ts](../src/lib/log/sink.native.ts), [lib/media.ts](../src/lib/media.ts). |
| `expo-clipboard` deprecated `content` removed (55) | [lib/log/share.ts:49](../src/lib/log/share.ts) uses `setStringAsync`. |
| `expo-sqlite` | `openDatabaseSync`, `enableChangeListener`, `defaultDatabaseDirectory`, `deleteDatabaseSync`, `closeSync` are all stable 54 → 57. |
| Legacy architecture removed (55) | No `newArchEnabled: false` anywhere. Already on the new architecture. |
| `expo-av` removed, `expo-video-thumbnails` deprecated (55) | Not used. |
| `expo-camera` | `CameraView` + `useCameraPermissions` unchanged — [qr-scanner.tsx](../src/components/campaign/qr-scanner.tsx). |
| `experiments.reactCompiler` / `typedRoutes` | Both still valid config in 57. React Compiler is stable in React 19.2; the documented NativeWind incompatibility does not apply here. |
| `eas update --environment` now required (55) | No EAS Update in this repo yet. |
| `notification` field removed from app.json (55) | Not present. |

### Off Expo's compatibility matrix — smoke-test by hand

- **`react-native-paper ^5.15.3` — the biggest unknown.** Its peer ranges are all
  `*`, so `expo install --fix` and `expo-doctor` will *not* warn. Paper is not on
  Expo's compatibility list and touches React Native internals; RN 0.86 could
  break `Dialog`, `TextInput`, `FAB` or `SegmentedButtons`. The entire UI rests
  on it — [`<DsDialog>`](../src/components/ui/ds-dialog.tsx) alone is used by
  every screen.
- **`drizzle-orm ^0.45.2`** — the expo-sqlite driver plus `useLiveQuery` and
  `useMigrations`. The bundled SQLite version moves across three SDKs.
- `react-native-qrcode-svg ^6.3.21`, `@expo-google-fonts/*`,
  `react-native-keyboard-controller`.

### Dead weight to drop while you are in here

Zero imports anywhere in `src/`: **`expo-symbols`, `expo-status-bar`,
`expo-system-ui`, `expo-web-browser`**. Removing them cuts four native modules
from the upgrade surface. (`expo-linking` stays — it is an `expo-router` peer;
`expo-font` stays — `@expo-google-fonts/*` needs it; `expo-splash-screen` stays —
used as a config plugin.)

## 5. New features worth considering

None are required. Listed for the record.

| Opportunity | Verdict |
|---|---|
| **SQLite Inspector DevTools plugin** (55) | **Take it.** Live database browsing, zero code. A real win given the `characters` / `actual_state` split. |
| **Native Tabs** (`expo-router`, 55) | **Skip.** [(tabs)/_layout.tsx](../src/app/character/[id]/(tabs)/_layout.tsx) pins the header to 56 dp and injects a custom `headerLeft` on the first tab; native tabs would reopen both decisions. |
| **Expo UI stable** — SwiftUI / Jetpack Compose (56) | **Skip.** The app is committed to Paper/MD3 driven by `useProphecyTheme()` tokens. Adopting Expo UI would fork the design system. |
| **`@react-native-vector-icons/*` migration** | **Skip for now.** `@expo/vector-icons` v15 is still published; only two import sites. |
| **Hermes bytecode diffing** — ~58 % smaller OTA updates (56) | Only relevant if EAS Update is adopted. No OTA today. |
| **iOS precompiled XCFrameworks + Android Kotlin compiler plugin** (56) | Free on upgrade, nothing to do. ~16 % faster iOS builds, ~40 % faster Android cold start. |
| **`expo-sqlite` tagged template literals** (55) | Redundant — Drizzle already provides type-safe parameterised queries. |
| **`Stack.Toolbar`, Colors API, Apple Zoom transitions** (55/57) | Optional polish. |

## 6. Upgrade plan

Do it **one SDK per commit.** Going 54 → 57 in a single step mixes the router
split, the `fetch` swap and the Hermes swap into one un-bisectable failure.

### Step 0 — prep

1. Branch off `dev`.
2. Add an explicit `actions/setup-node` (Node 22) step to
   [ci.yml](../.github/workflows/ci.yml).
3. Record a green baseline: `bun run test`, `bunx tsc --noEmit`, `bun run lint`.
4. **Export a character to JSON.** You will need it to verify the database
   survived.

### Step 1 — SDK 55

```bash
bunx expo install expo@^55 && bunx expo install --fix
```

Then verify `node_modules/ajv` is 6.x, run `bunx expo-doctor`,
`bunx tsc --noEmit`, `bun run test`, then prebuild and run on Android.

### Step 2 — SDK 56 (the big one)

```bash
bunx expo install expo@^56 && bunx expo install --fix
```

Then, in this order:

1. `npx expo-codemod sdk-56-expo-router-react-navigation-replace src`
2. Remove the three `@react-navigation/*` dependencies from package.json.
3. Add `@expo/vector-icons: ^15.0.2`.
4. Bump `typescript` and `eslint-config-expo`.
5. `bunx expo-doctor` — the router/navigation coexistence check fires if step 2
   was missed.
6. Full device pass: **campaign attach / join / leave against a real relay** (the
   `fetch` swap), memory profile on Android (Hermes V1), and every Paper dialog
   and input across all screens.

### Step 3 — SDK 57

```bash
bunx expo install expo@^57 && bunx expo install --fix
```

Confirm both config plugins survived native regeneration. Measure Reanimated
memory; if it regresses badly, flip `useHermesV1`.

### Step 4 — data-safety gate (do not skip)

The forward-migration harness
([src/db/migrations.test.ts](../src/db/migrations.test.ts)) runs against
`better-sqlite3`, **not** expo-sqlite. It cannot catch a bundled-SQLite version
change across three SDKs. Before any tester build:

1. Install the **current** build; create characters, campaigns, effects.
2. Install the upgraded build over it. Confirm the `0000 → N` chain tops up,
   `VACUUM INTO` in [db/backup.ts](../src/db/backup.ts) still works,
   `defaultDatabaseDirectory` is unchanged, and `useLiveQuery` still reacts.
3. Re-import the JSON exported in Step 0.

Testers run mixed versions. A broken top-up path is unrecoverable for them.

### Step 5 — docs

Update [DEV.md](../DEV.md) (the "Expo 54 specifics" callout and the versioned
docs link), [CLAUDE.md](../CLAUDE.md) (stack section), and
[README.md](../README.md) if it names the SDK.
